## 1. Locked architecture decisions (plan, 2026-09-05)

1. **Delivery model: Build-Locked only** (no continuous/CDN mode). Nothing is "live" until a **Build Snapshot** is cut: `{sourceRevision, localizationRevision, config} → immutable manifest export` (mirrors the dossier's "what shipped is what was tested" enterprise differentiator; automotive HUD/industrial/arcade customers).
2. **AI vertical = full Quality Technologies stack modelled on Phrase:** **MT Optimize** (glossary-aware post-edit LLM pass), **QPS** (Quality Performance Score 0–100, second independent LLM-as-judge call over MQM-style dimensions accuracy/fluency/terminology/tone), **Auto-Routing** (per-project QPS threshold; below → human "Needs Review", above → auto-advance; = Smartling-style confidence routing). Base blueprint mapping: Strings ↔ Phrase Strings, review UI ↔ Phrase TMS CAT editor, workflow ↔ Phrase Orchestrator (Trigger → Action), routing ↔ QPS + Auto-Routing, LQA ↔ Auto LQA (MQM 2.0), glossary post-edit ↔ MT Optimize.
3. **Demo reliability as a Tier-1 feature:** real API calls by default (~80%); **Provider Health panel** (P50/P99 latency, error rate, circuit state per provider); **"Simulate Provider Outage"** toggle for interviews; on real/simulated failure fall back to a **seeded demo tenant** (one shared `DemoStringPool` composed differently per tenant): *Auroraline Automotive* (HUD), *Ferrix Industrial Systems* (embedded), *Pinnacle Arcade Co.* (cabinet), + 2 generic SaaS/mobile tenants; tenant switcher + live/fallback toggle in the global top nav.
4. **Sequencing: depth-first** — finish Tier 1 completely before Tier 2/3.
5. **Orchestrator = config-driven ordered Trigger→Action list, not a visual node canvas** (React Flow rejected as frontend risk; maybe Tier-3 polish).
6. **Hand-written boundary (Phase 3):** prompt construction, response parsing/validation, Auto-Routing threshold logic, semantic-cache threshold logic, COMET-Kiwi integration, provider abstraction for vLLM, eval-runner orchestration are hand-written by the user; boilerplate (FastAPI app setup, Pydantic models, routing, Dockerfile, requirements, the thin .NET HTTP client) may be scaffolded.
7. **Roadmap:** Phase 1 Foundation + Orchestrator + Build Lock (manual actions Mark Translated/Send to Review/Approve; status New→Translated→Reviewed→Approved) → Phase 2 Automated MT + Credits (Google Translate action, character-based credit estimator, provider-health scaffolding) → **Phase 2.5 Vendor Marketplace** (confirmed; second interview centerpiece) → Phase 3 AI Vertical (LLM adapter reusing the `LlamaApiClient` pattern, MT Optimize, QPS, Auto-Routing, token-based pricing beside character-based, provider-health completion, seeded tenants). Deferred/cut: continuous delivery, node-canvas builder, real multi-tenant partitioning, SSO/SCIM, pseudo-localization, in-context preview overlay, real fuzzy TM engine.
8. **LLM provider (2026-09-05): self-hosted open-weight model on the user's own GPU served via vLLM** (OpenAI-compatible endpoint); commercial APIs (Bedrock, Azure OpenAI, Claude/OpenAI direct) ruled out. Candidates to *test*, not default-pick: Qwen2.5-7B-Instruct (priority for zh-CN/ja-JP), Llama-3.1-8B-Instruct, Mistral-7B-Instruct-v0.3; 4-bit AWQ/GPTQ by VRAM; 3-process architecture .NET → FastAPI → vLLM. `GoogleTranslateProviderService` **stays in .NET** as the deliberate "Legacy MT" baseline (real Google Cloud Translation v2 Basic/NMT call; labelled `[MOCK-XX]` fallback in non-prod, throws in prod).

## 4. Pending AI-service design (Architecture & Workflow doc, Parts B–G; nothing implemented)

- **New DB fields/entities:** `LocalizationTranslation.RawMtText` + `RawMtQpsScore`; `GlossaryTerm` (project, locale, source/target term, notes); `TranslationCacheEntry` (pgvector `SourceEmbedding`, `CachedTranslation`, `HitCount`, timestamps); `EvalGoldenCase` (source, gold translation, `Category` short-label|warning-message|idiomatic|legal-disclaimer); `EvalRun` (`PipelineConfig` legacy-only | legacy+optimize | +cache | +glossary; AvgCometKiwi, AvgQpsScore, GlossaryAdherenceRate, PlaceholderPreservationRate, CacheHitRate, AvgLatencyMs, TotalCostUsd); `EvalCaseResult`; `LedgerEntry` + `UnitsConsumed`, `UnitType`, `RealCostUsd` (real dollars kept separate from fictional marketplace credits). ≈7 new/changed tables.
- **Eval-harness-first:** build the golden set (30–50 hand-authored cases across the 5 locales and categories; long/idiomatic strings where Legacy MT should struggle) and the metric runner **before** the AI service so every stage has something fixed to measure. Metrics: COMET-Kiwi (local `unbabel-comet`, free per call), QPS, glossary adherence (deterministic string match), placeholder preservation (`{count}`-style tokens), cache hit rate, latency, cost.
- **Semantic cache:** embed source, cosine-search per project+locale, start at ≥0.95 (false hits silently change meaning — "cache poisoning meaning drift").
- **Pipeline:** Legacy MT (Google, .NET) → cache check → MT Optimize (self-hosted LLM, glossary-grounded) → QPS + COMET-Kiwi → auto-route (≥ threshold stays "Translated"; below → `NeedsReview`) → flagged rows to the existing Marketplace flow (whole-locale jobs; vendor sees flagged rows — option (b)).
- **FastAPI contracts:** `POST /translate-and-optimize` → `{optimizedTranslation, cacheHit, tokensUsed}`; `POST /qps-score` → `{score 0-100, flaggedIssues[]}`; `POST /comet-score`; `POST /run-eval` → `EvalRun` metrics; `POST /auto-route` → `{needsReview}`. Auth between .NET and Python = shared-secret header like `x-api-key`. Cost tracking "built for real": .NET writes `LedgerEntry(Source="AI", RealCostUsd from an amortised $/1K-token rate)`; Legacy MT ledgered at Google's published character rate → three-way cost-per-resolved-query comparison (Legacy MT vs LLM-Enhanced vs Marketplace).
- **Interview checklist (Part G):** baseline vs enhanced COMET/QPS, cache hit rate and savings, glossary adherence before/after, % flagged and dominant categories, cost per resolved query by path, the named failure mode found and next step — each answered with a real `EvalRun` number.
- **Framework choice:** LangChain for this pipeline (linear, two conditionals, PGVector cache, structured output); **reverse to LangGraph only if** an in-pipeline human pause or repair loop back into MT Optimize appears (`07-…` §3.1).

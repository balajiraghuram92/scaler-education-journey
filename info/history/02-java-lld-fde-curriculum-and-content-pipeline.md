## 2. Quality tiers & word counts

- **Tier 1** — hand-authored/Published: Modules 1–4 (17 lessons at the time); two dense *Concepts Covered* paragraphs (mechanism, then consequences/trade-offs), one named scenario, 5-step Practice Loop, real Evidence paragraph, code blocks; flagship = Lesson 4 (`04-oop-3-polymorphism-interfaces`, with concept check + the first real coding exercise).
- **Tier 2** — machine-templated `Draft` (Modules 5+, ~165 lessons across Java + FDE as of 2026-08-28): thin, no code/diagrams/exercises/MCQs. Purpose of the whole content push: lift Tier 2 to Tier 1 using real source material. (By 2026-09-01 all 152 FDE lessons were authored — Tier gap now applies mainly to Java expanded modules.)
- **Word counts:** foundational/conceptual 500–800; advanced mechanism (SOLID, patterns, concurrency, threading, generics) 1200–1500 — a cap for depth, not licence to pad.
- **Target learner:** developers with 7–8+ years of experience; content must not be basic. Voice: second person, present tense, direct.

## 3. The lesson authoring contract (Master Reference Guide v2.3 — kept live in `.notes/`)

Body sections in exact order: `# Title` → `## Concepts Covered` → `## Practical Backend Scenario` → `## Practice Loop` (exactly 5 steps; step 1 setup, step 3 diagnostic/measurement, step 5 review/refactor) → `## Evidence of Understanding` → `## Suggested Extension`; then a single-line `Reference:`.
Frontend renders those five as fixed panels — do **not** invent new top-level `##` sections. (H3/H4 hierarchy inside sections was added 2026-09-21 for RAG chunking — §7.)
Rules: ground every claim, no invented APIs; no generic filler ("test: swap the topic — still true? delete"); no bullet-list Concepts; one scenario followed through; code only if real compiling-quality; respect prior lessons; `SOURCE_TYPE` = `FROM_MATERIAL` | `LLM_GENERATED` on every MCQ and exercise block (conservative: unsure ⇒ `LLM_GENERATED`); MCQ = 4 options A–D, exactly one correct, `CORRECT_ANSWER_KEY`/`INDEX` consistent; concept checks max 2/lesson and **never** hard-code `initialSelectedOption`/`initialSubmitted`; architecture diagram only if the flow is non-obvious and adds beyond the scenario (prefer before/after contrast for OOP lessons); exercises appear only if `lessonExerciseAssociations.js` has an entry *and* the exercise exists.
File organisation for Local-LLM parsing: YAML metadata block, `<!-- CHAPTER_BODY_START/END -->`, `MCQ_SECTION`, `EXERCISES_SECTION`, `FURTHER_READING_SECTION`, manifest of external zips + validation checklist.
Optional side content: `LessonResource` (`StudyGuideTopic|HackMdPre|HackMdPost|PdfNotes|HorstmannRef`), `LessonCodeComparison` (before/after), `LessonDiagram` (SVG/spec), `Problem` (static problem card).

## 4. Content pipeline & the write-once seeding gotchas

**Flow:** Scaler material → Claude authors lesson `.md` (+ MCQs/exercises) → self-review checklist → Local LLM ingests into C# seed data (`JavaVerticalSeedData.cs`, `FdeCurriculumSeedData.cs`) + JS data → local Docker verification → commit with **`[deploy]`** → CI → `--seed-reference-data` → PostgreSQL. (Local LLM = "Gemini"/3.8 Flash/Qwen etc.; models suggested for local authoring: gpt-oss-120b for prose, Qwen3-Coder-30B for exercise/test code.)
Principles: the LLM authors, a human approves; never flip `ContentStatus` to `Published` without a human read-through; prove the loop on one chapter first (`patterns-01-solid` was the recommended pilot); match Tier 1, not Tier 2; don't touch the exercise engine's trust boundaries.

**Gotcha 1 — write-once seeding.** Lessons whose `ContentBody` contains `## Practical Backend Scenario`, `## Practice Loop`, `## Evidence of Understanding` are never overwritten. `GetAuthoredLessonContent`+`BackfillLessonContent()` runs every start but only replaces bodies that `NeedsLessonContent()` judges bare (<~900 chars/missing headers); `GetExpandedModules()`+`EnsureExpandedModules()` only writes when the row is missing/empty or status `Outline`. To force a reseed: `UPDATE lessons SET content_body='', content_status='Outline' WHERE slug='<slug>';` then restart/`--seed-reference-data` — **and** ensure `BackfillLessonContent` sets `ContentStatus='Draft'` when writing. Proposed durable fix (never confirmed applied): `BackfillExpandedLessonContent(db, courseId)` gated by e.g. `Draft && ContentBody.Length < 1200`.
**Gotcha 2 — deploy trigger.** Deploy runs only if the commit message has `[deploy]` (or manual dispatch); 18 commits once silently failed to ship.
**Gotcha 3 — C# verbatim strings.** Lesson bodies live in `@"…"` strings: every literal `"` must be `""`; one bad `"` produced hundreds of cascading errors (the `URGENT-fix-broken-csharp-quote-escaping` incident, 2026-09-22, lessons 18–22 in `GetAuthoredLessonContent`). Local LLMs also hand-authored EF migrations and mis-resolved merges — always say "generate migrations with `dotnet ef migrations add`" and "replace the named block wholesale".
**Gotcha 4 — verification.** Compilation is mandatory evidence (static inspection missed an `Options.Create` name collision); a "done" claim is a lead to re-check. No .NET SDK/Maven in Claude's own shell — ask the user to run builds.
**Gotcha 5 — lesson-slug collisions** (see Module 4 vs Spring numbering above) and `git config core.fileMode` / `chmod +x scripts/*.sh` after a fresh WSL pull.

**FDE 2026-09-01 deployment investigation (kept in full — a good template for any "content didn't update" bug):** after finishing all 152 authored FDE lessons the live site still showed generic placeholder text. Root cause = the write-once guard `if (string.IsNullOrWhiteSpace(lesson.ContentBody)) lesson.ContentBody = content;` in `FdeCurriculumSeedData.Seed()` — every FDE lesson row had been created with placeholder text in late August before authoring existed. Migrations/seeding are **not** run on API start (`Program.cs` never calls `MigrateAsync`); `deploy-single-ec2.sh` runs `--migrate` then `--seed-reference-data` as one-shot containers before starting the API; the DB container is reused (restore-from-backup only if the DB is empty). Fix: blank the placeholder rows (`UPDATE lessons … FROM course_modules m, courses c WHERE c.slug='fde-curriculum' AND l.content_body NOT LIKE '%## Practical Backend Scenario%'`), re-run seeding on EC2 → 152/152 authored; then a full delete-and-recreate of the course as DR proof (also 152/152). Verification fingerprint: `content_body LIKE '%## Practical Backend Scenario%'` (placeholder uses `## Worked scenario`). Detours: wrong DB name (`studytracker` decoy vs real `StudyTrackerDB`), stale cached local image (`docker run` doesn't re-pull an existing tag → pull and pin the digest). FK notes: `courses→course_modules→lessons→lesson_resources/problems/course_domain_links` cascade; knowledge-atlas links mostly `SET NULL`; **`study_task_content_links.lesson_id` is `RESTRICT`** (was 0 rows — recheck before deleting a course); **never delete the `Verticals`/`Tasks` rows for FDE Curriculum/FDE Self-Study** (seeder returns early without them). `info/.notes/cleanup-redundant-expanded-modules.sql` (kept; non-md) is the matching cleanup script (diagnostic block first; safe on any env).

## 7. Interactive exercise engine (built; architecture retained)

- **Product intent:** lessons become an active loop (read → scenario → concept checks → open exercise in-lesson → edit multiple Java files → run against trusted tests → inspect compiler/test evidence → optionally reveal reference solution). Not a generic online IDE: Neuralascent owns exercise definitions, tests, POM, runner image, limits and evidence; learner controls only editable source files.
- **Decisions:** lesson-embedded (ChapterReader), compact-first with expandable workspace, multi-file first, trusted infra/untrusted learner source, disposable execution (fresh workspace + fresh container per Run), Git/filesystem source of truth, same-EC2 execution initially, Run ≠ View Solution (lazy `GET`, persistent accessible disclosure), immutable images via GHCR with the runner referenced by digest (and a local `:deployed` tag so image pruning can't delete it), concurrency 1 on the 1 GB EC2, PostgreSQL preserved, deterministic definitions (no per-submission LLM judging in v1).
- **Package:** `exercises/java/<pathway>/<topic>/<slug>/` = `exercise.json` (id `java-lld-…`, `lessonSlug`, `title`, `language`, `difficulty`, `estimatedMinutes`, `runtime{profile:"java-maven", javaVersion:11, timeoutSeconds}`, `files[]` with `editable` flags, `testSuite` (`visible:false`), `evidence[]` mapping plain-English claims → JUnit method names) + trusted `pom.xml` + `starter/` + `tests/` + `solution/`. Canonical first exercise: `Point`/`ThreedPoint` (`oop-3/point-threedpoint`), then `oop-2/rider-entity`.
- **Runner:** generic Maven/JDK image in `runner/java/` (`run.sh` = `mvn --batch-mode --no-transfer-progress test`), Maven cache named volume, timeouts (`ExerciseExecution__MaxExecutionSeconds` 120 s default, memory ~768 MB), Surefire XML as the structured result source, golden solution as integrity check, submission whitelist (`ExerciseSubmissionValidator`), path-containment/symlink rejection in `ExerciseRepository`. Never give the public API arbitrary Docker control; no Docker socket/secrets in the learner container.
- **API:** `POST /api/exercises/{exerciseId}/run` body `{"files":[{"path","content"}…]}` (editable files only) → `ExerciseExecutionResponse` (`api/Models/ExerciseDtos.cs`); solution via lazy GET. Frontend: `ImplementationExercise.jsx`, `useExerciseWorkspace.js`. Mistakes that became lessons: fixed reader width, Run vs Check identical, moving Reveal/Hide control, runner image pruned, `Options.Create` name clash, test-DI drift, stale browser assets.
- **Hand-wiring recipe for a new exercise (11 steps):** locate original solution zip; read all `.java` + the test; **strip Lombok** (explicit user decision: plain constructors/getters — avoids annotation-processor risk in the sandbox); add only what the test imports as test-scope deps (`org.reflections:0.10.2`, `mockito-core:5.5.0`, `mockito-junit-jupiter:5.5.0`); read the test line-by-line for the exact graded contract (e.g. Facade must hold *zero* raw dependency fields); pom at exercise root; complete `solution/`; `starter/` = non-editable fixtures verbatim + TODO bodies in editable classes; official test byte-identical except Lombok helpers; `exercise.json`; manual verify (assemble pom+`solution/src`+`tests` in a temp dir, `mvn test` expect pass; repeat with `starter/src`, expect failure); `info/.notes/verify-new-exercises.sh` (kept) batch-checks.
- **Wired so far (as of 2026-08/09):** Lesson 15 and 16 complete (Adapter×3, Facade×3, Flyweight×2, Decorator×3, Factory, Abstract Factory×3), Strategy×3, Observer×3, Factory-board-game/database, TicTacToe undo+win-check, Hotel (add/get/book rooms, invoice), 65 exercises across 9 topics/17 lessons by 2026-09-21, plus Parking Lot ×2 (2026-09-22). **Not yet wired:** Splitwise (Spring/JPA — needs the `java-maven-spring` profile), BookMyShow, most `practice-pool` items (unzipped batches 1–4; see `exercises/practice-pool`; **Windows checkouts need `core.longpaths` — avoid touching practice-pool**).
- **Runner profiles/Spring:** future Spring labs = student Spring project + tests + temporary Postgres (resource-heavy; keep model extensible). The `java-spring` runner image (Java 17) exists per 2026-09-22 handoff; Splitwise wiring pending.
- **Historical decision — "Lombok in exercises":** stripped; **"test-scope deps ok"**; **no subagents for exercise wiring** (correctness-sensitive); **no invented `conceptChecks`**; **lessons 21–23 blocked until real Scaler material** (then later authored via the hierarchy prompt); **`[deploy]` tag discipline**.

## 1. Scope rule (set 2026-09-04, in `CLAUDE.md`)
Two unrelated things are called "AI" in this repo:
1. **AI vertical (curriculum content)** — courses *about* AI/LLM engineering (e.g. Model Economics Matrix / RAG eval-harness project). **Authored entirely by hand by the user.** Claude must never generate a Local-LLM/Gemini prompt to write, seed or edit it, and must not treat pasted AI-vertical project descriptions as a request to produce seed-data prompts; role limited to reading/organising notes.
2. **AI integration (site infrastructure)** — LLM plumbing inside the running app (`api/Endpoints|Services|Models|Options|Program.cs`, `app/src/**`, `docker-compose*.yml`, `appsettings*.json`). Normal read-then-prompt workflow **except** that for the AI Learning Agent, `ai-agent/` and its supporting infra are hand-written by the user (`07-…` §1).
Rule of thumb: touching `api/Data/*SeedData.cs` or lesson content for an AI-topic vertical ⇒ hand-authored, no prompt.

## 2. Auth, approval, TOTP and hard-capped Llama chat (built Sep 4–6; committed to `main`)

**Why:** the user wanted a learner-facing chatbot with an explicit security requirement — "bot attacks are increasing… to save my bank from getting looted due to AI use I need this for sure, no compromise on that."
**Delivery:** Claude wrote prompt packages (`neuralascent-auth-and-chat-gemini-prompts.md`: Part A auth foundation + six Part-A corrections, Part B mandatory TOTP + corrections, Part C Llama chat + $2/day cap, final corrections, then two rounds of code-review findings); the user's Gemini/3.8-Flash applied them; Claude reviewed line-by-line. Backend was **never compiled in Claude's environment** (no .NET SDK/Docker); the user later committed "fixed compiler issues" fixes that were not reviewed. Frontend `npm run build` was really run.

**Locked architecture**
- Public self-serve signup (`POST /api/auth/signup`) → `PendingApproval` → admin approve/reject in a dashboard → automated email either way. (An invite-only pivot was reverted; only the *approval decision* is admin-gated.)
- Two-step login: `POST /api/auth/login` verifies the password and returns a short-lived single-purpose `MfaChallenge` id (never a cookie); `/totp/enroll/start`+`/enroll/confirm` (first time) or `/totp/verify` exchanges a correct 6-digit code for the httpOnly JWT cookie `na_auth` (`SameSite=Lax`, `Secure` on HTTPS, 12 h). **TOTP mandatory for everyone incl. admin** (RFC 6238, Google-Authenticator compatible; chosen over SMS/email OTP/paid MFA).
- **Chat:** Meta Llama API (`https://api.llama.com/v1/`, OpenAI-compatible), lesson-scoped conversations behind login, **hard $2.00/day aggregate cap checked *before* any model call**, independent 500-requests/day backstop, mandatory character-count fallback token estimate `ceil(chars/4.0)` when usage is unparseable (never treat unparseable usage as zero cost).
- **Password hashing:** PBKDF2-SHA256, 210,000 iterations, 16-byte salt, constant-time compare, *stored* iteration count used on verify. **TOTP secrets:** AES-GCM-256, random 12-byte nonce, `nonce‖ciphertext‖tag` Base64. **Rate limit:** ASP.NET `RateLimiting` fixed window `"AuthPolicy"` 10 requests/15 min on signup, login, `totp/enroll/confirm`, `totp/verify`.
- **Admin endpoints re-check DB state each call** (`Role=="Admin" && Status=="Approved"`) — never trust the JWT role alone. **Lost authenticator:** `POST /api/admin/users/{id}/reset-totp`; for the admin's own lockout a documented manual SQL (`UPDATE app_users SET totp_enabled=false, totp_secret_encrypted=NULL, last_accepted_totp_counter=NULL WHERE email='…'`).
- **First admin:** `--seed-admin` CLI mode reading `ADMIN_EMAIL`/`ADMIN_PASSWORD`; fails loudly and exits 1 if missing; deliberately *not* in `DbSeeder`/`--seed-reference-data`.
- **`x-api-key` middleware left untouched** — prod Nginx injects the real key server-side for all `/api` (an early plan to exempt `/api/auth` would have been a regression).
- **TotpService (verified correct):** 20-byte secret, unpadded Base32, `otpauth://…algorithm=SHA1&digits=6&period=30` (SHA1 required by Google Authenticator), HMAC-SHA1 with RFC 4226 dynamic truncation, ±1 step drift, **replay protection** via `LastAcceptedTotpCounter` (reject `counter <= last` before computing), fixed-time compare; brute-force lockout: `MfaChallenge.FailedAttempts` ≥5 burns the challenge.
- **Data model:** `AppUser` (Email unique, PasswordHash/Salt/Iterations, Role User|Admin, Status PendingApproval|Approved|Rejected|Disabled, DisplayName, CreatedAt, DecidedAt, DecidedByUserId self-FK Restrict, LastLoginAt, TotpSecretEncrypted, TotpEnabled, LastAcceptedTotpCounter); `MfaChallenge` (Guid, UserId, Purpose Enrollment|Login, ExpiresAt +5 min, ConsumedAt, FailedAttempts — a table row, never a JWT); `ChatConversation` (UserId cascade, LessonId SetNull); `ChatMessage` (Role, Content, ClientRequestId idempotency, Prompt/CompletionTokens, `UsageEstimated`, `EstimatedCostUsd decimal(10,6)`, LatencyMs, ErrorMessage). Migrations `20260904103000_AddAppUsersTable`, `20260904111500_AddTotpMfaChallenges`, `20260904120000_AddChatTables` — **must be tool-generated** (`dotnet ef migrations add`; hand-authored files desync the model snapshot).
- **Files:** `api/Options/{Auth,Email,LlamaApi,Budget}Options.cs`; `api/Services/Auth/{IPasswordHasher,Pbkdf2PasswordHasher,IJwtTokenService,JwtTokenService,TotpSecretProtector,TotpService}.cs`; `api/Services/Email/{IEmailNotificationService,SmtpEmailNotificationService}.cs` (`System.Net.Mail.SmtpClient`, works with Gmail/SES/SendGrid/Resend); `api/Services/{LlamaApiClient,BudgetGuardService}.cs`; `api/Endpoints/{Auth,Admin,Chat}Endpoints.cs`; frontend `AuthContext.jsx`, `useAuth.jsx` (re-export), `ProtectedRoute.jsx`, `ChatWidget.jsx`, `AuthPage.jsx` (tabbed sign-in/up), `AdminDashboard.jsx` (approvals + AI-usage budget); `qrcode` npm package (client-side QR so the TOTP secret never crosses the network).
- **Commits:** `2b8fd35`, `d51375e`, `0f0bb25` (localization), `2fff426` (YAML fix), `054c3ae`, `9e8ad89`, `a660f95`.

**Regression saga (2026-09-04/05) — read if anything looks reverted:** a GitHub-Desktop auto-stash re-applied over newer work via a botched conflict resolution reverted all security fixes and left `Program.cs` non-compiling (duplicate `jwtSecret`, unclosed braces, literal `<<<<<<< Updated upstream` markers). Recovered via `git reflog`/`git stash list` and `git stash apply` (not `pop`). Fixed **four** hardcoded-fallback-secret instances: `Program.cs` JWT key, `TotpSecretProtector.cs`, `LlamaApiClient.cs` mock response with no `IsProduction()` guard, and the previously-unseen `JwtOptions.SecretKey` default + `JwtTokenService` legacy merge that bypassed the throw. Rule now: production throws if a key is missing; dev generates a **fresh random key per process** (`RandomNumberGenerator.GetBytes(32)`), never a fixed string; compose requires `Smtp__*`/`LlamaApi__ApiKey` with `${VAR:?must be set}`. Final verification = repo-wide grep for the known secret substrings and conflict markers (clean). Lessons: re-state "run `dotnet ef migrations add`" and "replace the named block wholesale" in every prompt; a local LLM won't reliably recall earlier corrections.

**Known accepted limitations:** `BudgetGuardService.TryReserveRequestAsync` check-then-act race (bounded blast radius); Llama usage field names unverified (parser isolated in `TryParseUsage`); `LlamaApi:PricePerMillionInput/OutputTokensUsd` are placeholder `0` in `appsettings.json` — set from real pricing before trusting spend accounting; end-to-end smoke test (signup → approve → login → TOTP → chat → cap trips) is the real gate. Later: local `docker compose` runs need real `JWT_SIGNING_KEY`/`TOTP_ENCRYPTION_KEY` (placeholders in `.env` crash the API, exit 139); `TotpSecretProtector` gained an `IHostEnvironment` ctor arg (test fixed with an inline `FakeHostEnvironment`); crypto tamper test uses `Assert.ThrowsAny<CryptographicException>` for macOS.
**Status:** completed and committed; the existing Llama chat (`ChatEndpoints.cs`) is the **precursor the AI Learning Agent replaces**; its auth layer is reused as-is (FastAPI validates the same JWT).

## 5. AI-platform TODO tracker (merged; 2026-09-01) — condensed backlog
**Purpose:** expand NeuralAscent from a study tracker into a technically serious platform: identity, authorization, tenant-safe data access, conversation ownership, cost controls, observability, progressive tutoring, support workflows, retrieval security, and (originally) a controlled .NET→Java/Spring migration (**now Python — `08-…` §A.8**). Incremental: auth + quotas + cost protection are launch prerequisites; RAG, auto-completion and the migration are not prerequisites for the first protected tutor. Target model: **Meta Muse Spark 1.2** (later 1.3 Contributor for the agent — `07-…`); a merge note says this tracker supersedes the standalone `neuralascent-chatbot-muse-integration.md`.
**§1.1 model decisions (Phase 0):** access path Meta Model API vs **OpenRouter (recommended default)** — record in `docs/architecture/ai-provider-decision.md`; **Standard vs Contributor pricing tier** — Contributor ~10–20× cheaper but Meta may train on prompts, so default **Standard** for anything with learner code/curriculum content.
**Architectural principles (13):** exact context before retrieval; authentication identifies the caller (never accept userId/roles/entitlements from the browser); authorization precedes retrieval; conversation UUID is not authorization; the LLM never grants access; provider keys stay server-side; cost is a controlled resource; telemetry processed before prompting (only compact summaries reach the prompt); tutor and support are distinct assistants; modular monolith first; provider-neutral AI interfaces; no arbitrary model-controlled mutation (tickets, completion, suspension, quotas, publishing are typed backend commands); evaluate rather than assume.
**Launch gates:** private prototype = Phases 0, 3, reduced 4; invite-only beta = Phases 0–5 + conversation ownership + basic ticket submission; public = all security/quota/audit/support/privacy/ops gates.
**Phases:** **P0** inventory (routes, endpoints, EF entities, `x-api-key` uses — is the shared key exposed in the production bundle?), trust boundaries (browser untrusted; retrieved chunks untrusted; PostgreSQL policy authoritative; provider token counts authoritative for reconciliation, estimates only for admission), 18-item threat model · **P1** identity (`app_user`, roles LEARNER/SUPPORT_AGENT/ADMIN, states, HttpOnly cookies, CSRF, invitation-only initially, session lifecycle) · **P2** authorization (enrollment/entitlement/visibility/solution-disclosure/future-concept policy, example policy JSON, enforce before retrieval, cross-vertical denial message, negative tests A→B) · **P3** AI gateway (provider-neutral `IAiChatClient`/`IEmbeddingClient`/`IRerankerClient`, forced `emit_tutor_response` tool call, `reasoning_effort` low/medium, admission pipeline *authenticate → status → authorize → ownership → payload → rate → concurrency → token estimate → user quota → global budget → idempotency → reserve → invoke → reconcile*, layered rate limits (6/min, 30/h, 100/day, 2 concurrent streams per user; support 15/h & 800 tokens; tutor 1500 tokens; global 20 concurrent provider calls), token/money quotas with price versions, `clientRequestId` idempotency, kill switches, abuse events) · **P4** current-context tutor (`PageContext` claim vs `ContextResolver` fact; 5-level hints; structured output JSON with `answerType/hintLevel/diagnosis/messageMarkdown/nextAction/sourceChunkIds/concepts/solutionDisclosure/confidence`; SSE events `accepted|route|token|source|usage|complete|error`) · **P5** admin AI-ops dashboard (usage overview, invocation explorer, quotas/kill switches with audit, alerts) · **P6** persistent learner state (lesson progress states, MCQ attempts, code checkpoints, resume) · **P7** conversation persistence + bounded memory · **P8** engagement telemetry + server-side completion policy (JSON policy, e.g. `BOTTOM_REACHED`, ≥180 s active, mandatory MCQ ratio;
